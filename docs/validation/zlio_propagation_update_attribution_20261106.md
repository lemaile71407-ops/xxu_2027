# runtime 248–254：IMU 传播、LiDAR 校正与后验速度状态

核验日期：2026-11-06。范围：对原始 `capture03` 做一次固定二进制、固定配置、固定输入的 1 倍速隔离前端回放，开启已有逐次更新诊断，判断指定窗口内新增相对误差首先出现在哪个阶段；随后复用同一诊断产物只读追查后验速度、偏置和 IMU 输入，没有新增回放。不修改业务源码、算法门限或噪声参数，不启动后端、Gazebo、Nav2 或实车。

## 结论

**这段新增 46.56 cm 偏差首先显现在 IMU 传播之后、当次 LiDAR 校正之前；整体也由传播阶段的误差增长主导。**

- 原始故障窗口 sequence 1257–1287 的 31 次更新全部复现，同一 epoch/sequence/纳秒时间戳逐项核对。后验 pose 矩阵最大差 **2.89×10⁻¹⁴**，Odometry 数值字段最大差 **1.98×10⁻¹³**，匹配点数和校正接受标记一致。完整消息没有逐字节相等，差别在浮点舍入量级，不表述为逐字节复现。
- 以 sequence 1257 后验作固定起点对齐后，下一次更新 sequence 1258 的 IMU 预测误差已达 **3.2503 cm**；同时间 LiDAR 校正后为 **3.2544 cm**。
- sequence 1259 更新前已为 **6.1113 cm**，校正后为 **6.3931 cm**。新增偏差已经在校正之前出现，不能把它归因为当次 LiDAR 更新才产生。
- 30 个相邻更新区间的误差向量分解闭合。沿最终水平误差方向投影，传播累计贡献 **+48.8961 cm**，LiDAR 校正累计贡献 **−2.3374 cm**，合计 **46.5587 cm**。

**“出现于传播阶段”不等于“IMU 传感器或输入一定有错”。** 传播从上一后验状态出发，上一轮 LiDAR/初始化造成的速度或偏置错误，也可能在后续传播中转化为位置漂移。本轮没有判定这几种物理根因，也没有宣称 LiDAR 校正完全无问题。

后续状态溯源进一步确认：**传播区间带入的后验速度误差主导本段位置误差增长**，并看到 LiDAR 更新会明显放大速度误差。seq1262 将水平速度误差从 0.5464 m/s 增至 0.7678 m/s，随后出现最大单次传播增长。它是明确的放大点，尚不是全运行的最早根因；完整方法和边界见第 6 节。

最新输入检查发现 capture03 的每帧单值时间，以及安装整形器与源码构建的行为差异，详见[输入点时间溯源](zlio_input_point_time_trace_20261106.md)。新的[端到端对照](zlio_point_time_e2e_20261106.md)显示有时序输入交付及同源改善，但未复现原 46.56 cm；不能由此或本报告的传播分解认定原漂移根因已修复。

这是指定起点之后新增相对误差的阶段归属，不是整个运行从启动以来首次异常的定位。起点归零来自对齐，并不表示当时绝对定位没有误差。原始输出到后端的身份与传输证据仍以[上一轮溯源](zlio_relative_motion_trace_20261106.md)为准。

## 2. 为什么这里能区分两个阶段

普通 `/odometry` 高频发布受回调和后验重传播影响，不能当成指定扫描端点的同时间纯预测。原采集未开启逐次更新诊断，因此本轮使用已有 `/frontend/lidar_diagnostics` 的 `prediction` 和 `corrected`，两者时间戳严格相同，corrected 与原子 frame 对齐。

[实际处理顺序](../../xxu_nav_2026/src/z-localization/src/frontend/src/odometry.cpp)为：

1. `predictTo(end)`：从上一后验状态顺序积分 IMU，推进至当前观测端点。
2. 在滤波更新前保存 `filter_.estimate()` 为 diagnostic prediction。
3. `filter_.update(...)`：执行当前 LiDAR 测量更新。
4. 将实际提交的结果保存为 corrected 后验，并发布 frame/diagnostic。

[消息转换](../../xxu_nav_2026/src/z-localization/src/frontend/apps/ros.cpp)与[诊断消息定义](../../xxu_nav_2026/src/z-localization/src/localization_interfaces/msg/FrontendLidarDiagnostic.msg)明确两者的时间、坐标和原始校正量。本轮不从外部高频话题插值猜测更新前状态。

## 4. 向量分解避免误把校正长度当误差增长

所有位置在同一固定世界坐标中表达。令 `e_k⁻` 为更新前预测位置减真值，`e_k⁺` 为后验位置减同时间真值：

- 当前传播区间贡献：`u_k=e_k⁻−e_(k−1)⁺`，已经扣除该段真实运动。
- 当前 LiDAR 校正贡献：`l_k=e_k⁺−e_k⁻`。
- 从起点后验出发：`e_final⁺=Σu_k+Σl_k`。

分解从 sequence 1258 计至 1287，不把起点 1257 之前的传播和校正混入。三维向量闭合最大分量差 **1.35×10⁻¹⁴ m**。

把两项向量和投影到最终水平误差方向后，得到 **48.8961−2.3374=46.5587 cm**。这不是把所有传播位移或所有校正距离的模长相加，也不把旋转误差和位置误差混在一起累加。

## 6. 后续只读溯源：传播带入的速度已经偏离

### 6.1 速度、偏置怎样取得

当前前端发布的线速度为 `v_body=Rᵀv_world`，所以由各条 prediction/corrected 的姿态恢复 `v_world=R v_body`；再通过本报告相同的固定世界对齐与仿真真值速度比较。没有将车体坐标速度直接与世界坐标速度相减。[发布实现](../../xxu_nav_2026/src/z-localization/src/frontend/apps/ros.cpp)

真值速度用同源时间位置的局部三次多项式导数估计，主结果使用 ±50 ms 窗口；±30 ms 与 ±80 ms 的敏感性复算在全部目标传播起点上的最大分量差为 **0.01349 m/s**。这不是精确的真值速度误差上界，但远小于下述 0.25–0.77 m/s 差异，且不是只用一个差分窗口给出结论。

- 陀螺偏置：发布角速度满足 `ω_out=ω_IMU−b_g`，用原 IMU 在同一整数纳秒时间的原样/线性插值恢复 `b_g`。
- 加速度偏置：同一传播区间中状态偏置不变。按原始 IMU 分段和[轨迹积分公式](../../xxu_nav_2026/src/z-localization/src/frontend/src/trajectory.cpp)构造速度对常量 `b_a` 的线性关系，由前后速度反算 `b_a`。
- 独立核对：速度已用于求 `b_a`，因此不再用速度相等自证；而用所得偏置、原始 IMU、起点状态独立计算末端位置与旋转。30 个区间最大位置分量误差 **8.88×10⁻¹⁶ m**，最大旋转矩阵元素误差 **2.00×10⁻¹⁵**。说明这些反算状态与实际传播输出一致，不是依据配置值猜测偏置。

这里验证的是记录到的状态与源码公式的数值闭合，并不证明这些偏置就是正确的物理标定，也不证明积分公式对真实运动的所有近似都足够准确。

### 6.2 上一后验速度如何主导位置增长

将每个传播区间的新增位置误差进一步分为：

`u_k = Δt·(v_post_previous−v_truth_previous) + q_k`。

`q_k` 保留当前区间惯性加速度、姿态/重力、偏置、积分近似和真值速度导数近似等剩余影响，没有把它简单命名为“IMU 传感器误差”。

沿最终水平误差方向的累计投影为：

| 项 | 累计投影 |
| --- | ---: |
| 传播区间起点速度误差 × 时长 | **+48.4268 cm** |
| 区间内惯性项等剩余贡献 | **+0.4694 cm** |
| 二者合计：传播贡献 | **+48.8961 cm** |
| LiDAR 位置校正贡献 | −2.3374 cm |
| 最终水平误差 | 46.5587 cm |

约 99% 的传播净投影来自带入区间的速度误差。此处统计的是带符号的向量投影，存在抵消，不能解释为 99% 的全部 IMU 样本“没有问题”。逐区间剩余项的最大水平模长约 **0.683 cm**；它也没有被忽略。

第一段 seq1257→1258：起点水平速度误差已经为 **0.2534 m/s**，仅其 0.12 s 传播就贡献约 **3.04 cm** 的水平误差向量长度；当前段其余项再贡献后形成约 3.25 cm 的预测误差。因此不能把第一段位置增长主要解释为本段积分突然算错。

### 6.4 偏置和 IMU 输入核对的限制

seq1257 恢复的 `b_g≈(−0.01540,+0.00607,+0.00870)` rad/s；反算 `b_a≈(−0.12497,−0.01020,−0.01609)` m/s²。它们是估计状态，不是与物理真值比较后的零偏结论。

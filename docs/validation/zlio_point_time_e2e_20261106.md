# RGL → ZLIO 点时间与固定窗口误差对照

核验日期：2026-11-06。范围：隔离仿真中重放原 capture03 的带时间戳安全速度指令，录制原始 RGL、整形云、补偿云、IMU、真值和两个 ZLIO；比较固定的 **177.807768442–181.399515141 s** 窗口。未调整前端算法、配置、噪声、门限或后端；未覆盖正式安装、默认导航链或实车。

## 结论

**点时间端到端保留已通过，本次同源对照的相对运动误差下降；原先 46.56 cm 故障没有复现，尚不能认定已修复。**

1. 正式轮的 **1839 帧、6905948 个原始 RGL 点**具有多个点偏移。逐点核对后，正确分支将 `header+offset_time` 保留到整形器、补偿器，再到 ZLIO 实际解码入口；补偿后的 **4641569 点**均通过相应记录及时间摘要检查。没有仅凭话题观察推定前端已经收到。
2. 两条分支同时使用同一原始云、同一补偿 IMU 和真值。两版整形器输出及补偿云的全部非时间字节一致；两侧各解码 1839 帧。旧分支全部点时间等于帧头，正确分支保留实际偏移。
3. 同一固定窗口内，后验末端相对水平误差从 **3.2705 cm → 0.4379 cm**，下降约 **86.6%**；七点水平 RMSE 从 **3.9480 cm → 1.8798 cm**。高频输出及 ±10 ms 端点敏感性也显示下降。
4. **不能把这张表写成原故障从 46.56 cm 修复到 0.44 cm。** 本次旧分支本身只有 3.27 cm，且新旧仿真真值路线不一致，未复现原故障前提。原包没有原始 RGL 云，不能补造其点偏移或追认当时实际扫描语义。

本轮还确认了实际产物核对的必要性：保留的候选插件未输出点时间；在仓库子目录直接运行既有构建脚本时，Git 会跳过补丁但返回成功。正式轮使用明确应用现有补丁、验证源码与产物后的独立构建。未修改正式构建脚本或安装目录。

## 2. 点时间如何逐段核验

对每个原始帧，以整数纳秒帧头精确关联五路消息：RGL 原始云、两侧整形云、两侧补偿云；1839 帧均完整配对，没有遗留单边帧。原始点时间跨度范围为 26.965–99.995 ms。

| 路段 | 实际检查 | 正式轮结果 |
| --- | --- | --- |
| RGL → 正确整形器 | 按真实抽样/有效点索引逐点比较坐标及 `timestamp=header+offset_time` | 全部一致 |
| 正确整形器 → 补偿器 | 用唯一时间匹配保留点，比较所有非 xyz 记录字节，覆盖自体过滤后的点 | 全部一致 |
| 补偿器 → ZLIO | 在实际 `decode` 后、入队前记录数量、时间最小/最大值及完整有序时间序列的 FNV-1a 64 位摘要 | 1839 帧全部一致 |
| 旧分支负对照 | 验证所有点仍为帧头，且 ZLIO 解码结果与该补偿输入一致 | 全部符合预期 |
| 两分支的其他输入 | 比较每帧整形云及补偿云的全部非时间字节 | 全部一致 |

此处覆盖实际解码入口，未把解码日志表述为全部点最终都被滤波器采样使用。FNV 摘要是完整有序时间序列的交付核对，不作为抗恶意篡改证明；构建及证据文件另记录 SHA-256。

177–182 s 的 50 帧也全部通过。第一帧实际 RGL 就包含 `offset_time`，3441 个不同偏移，范围 0.640–99.540 ms；因而正式轮并非仅配置 uniform 却接到瞬时点云。

证据：[逐帧点级核验](data/zlio_point_time_e2e_20261106/pointwise_transport.json)、[旧侧解码日志](data/zlio_point_time_e2e_20261106/capture04/old_decoded.jsonl)、[正确侧解码日志](data/zlio_point_time_e2e_20261106/capture04/new_decoded.jsonl)、[分析程序](data/zlio_point_time_e2e_20261106/analyze_e2e.py)。

## 4. 为什么还不能认定原 46.56 cm 已修复

相同速度指令没有产生足够接近的历史真值轨迹：在 177.807768442 s，新旧模型/传感器位置已相差约 **1.062 m**、姿态约 **8.39°**；到窗口末端，绝对位置差约 **1.343 m**，仅比较各自起点后的真值相对运动仍相差约 **25.82 cm**。

本轮预先按“七个时刻绝对及相对位置差均不超过 5 cm、旋转差不超过 2°”核对路线重现，结果未通过。该界限只用于本次重现判别，不是新的导航门限。未进一步确认物理初态、接触与指令交付的哪些差异造成路线偏移，不为使数值接近而调参。

另一个关键限制是源扫描语义：原包没有原始 RGL 云；本轮预检证明保留的一个旧候选产物实际不输出点偏移。**若源本来就是瞬时扫描，每帧同时间可以是正确语义，不能仅凭单值时间认定丢失了物理采样时刻。** 新的有时序 RGL 与历史原始数据并非可证明相同的传感器输入。

因此，本轮未确认“点时间丢失是原 46.56 cm 的根因”。原包中的速度更新、传播放大证据仍然有效，其最初根因继续以原输入分析为准。要宣称原故障修复，仍需先建立能复现原故障及运动前提的基线，再做单因素对照。

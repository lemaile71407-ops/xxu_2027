# 后端因子图、全局观测与 map → odom 设计研究

核验日期：2026-11-05 开始研究，2026-11-06 完成复核。对象：工作区 `xxu_nav_2026/src/z-localization` 当前源码，以及 2026-11-03 已有诊断包。范围：先验图定位主路径的观测信息、位姿约束、创新检验、优化与输出投影；UWB/回环仅检查接入边界，未完整审查其算法。没有修改业务代码、参数、安装或启动链，没有运行 ROS 节点、Gazebo、Nav2、实车或新的整包回放。

## 结论

**“前端相对运动 + 先验地图绝对观测 + 位姿图 + 最新锚投影”的架构合理；当前证据不支持重写因子图或更换优化器。主要未闭合的是噪声与相关性模型、恢复后的信任建立，以及失信输出语义。**

1. 当前实现的左右扰动、GTSAM 分量顺序、观测平方根信息和同时间锚转换，未发现本次可复现的代数错误。隔离探针对当前协方差/信息转换源码及已有 GTSAM 4.2 库执行了数值核对，结果见[探针结果](data/backend_factor_graph_review_20261105/contracts_results.json)。这不等于完成了所有图因子、实际安装产物或统计校准的验证。
2. 点面 Hessian 构造的是**固定地图、固定对应及局部高斯近似下**的测量信息。源码虽保留完整耦合、降秩方向、帧数降权和单次共模方差，但没有显式表达跨次地图误差、前端偏置及拼接轨迹误差的共享变量；不能把图边缘协方差直接视为已校准的真实误差界。
3. 新复算的故障片段中，runtime 248–254、177.807768442–181.399515141 s，名义 `map → odom` 最大矩阵元素变化仅 **3.55×10⁻¹⁵**。以片段起点对齐后，记录中的前端相对运动在 3.59175 s 内产生 **0.46559 m** 水平误差。该段预测误差增长发生在固定全局变换下的相对运动传播阶段；不是图持续修改 TF 造成的。2026-11-06 的[原始输出溯源](zlio_relative_motion_trace_20261106.md)进一步确认误差已在原始 ZLIO 后验发布消息中存在，后端输入适配没有生成这段误差；前端内部与前置补偿、时间语义仍待区分。
4. 同段七次地图观测均被 NIS 门拒绝。末帧预测水平误差 **0.36932 m**，已有诊断计算的配准测量误差 **0.01474 m**，NIS **66.01689/6**。拒绝计算符合其假定模型，但这说明系统必须有可靠的失信恢复路径；不能依赖常规小误差门自行纠正模型之外的偏差。
5. 失信时输出使用最后可信传感器位姿，并反算随里程计运动而变化的 `map → odom`。这个发布变换与图的名义变换不同，恢复时的输出跳变量不能直接当成图优化校正量。

历史重复回放、候选选择缺陷和固定源振荡的权威证据继续归[冻结释放复测报告](data/rgl_full_20261031/map_speed_parameters_20261103/freeze_retest_20261103/README.md)；本报告只增加设计研究和本次数值复核。

### 合理之处

- 不把前端的两个绝对位姿边缘协方差直接相加来充当相对运动噪声，避免混入共同规范误差；里程计边使用独立过程模型。这是合理的建模选择，但其独立性与参数仍需实验支持。
- 普通地图约束允许仅约束可观方向；不会为单面/走廊不可观方向人为构造满秩观测。恢复则要求完整位姿，这与重新建立全局锚的职责一致。
- 图预测先提交，再在同一预测图上检验一批外部观测，接受后再加入因子，避免当前观测先更新图、再用更新结果检验自己。
- 图变量间联合边缘协方差保留交叉块；它没有把多个共享图状态误当成独立状态。

### 边界与风险

- 里程计边的 `Q` 是各向同性平移/旋转对角模型，不包含偏置状态、前端相邻增量之间的长期相关或方向相关噪声。
- 当前 YAML 及诊断快照的过程方差为 `q_t=0.0005·Δt+0.0002·d`（m²），`q_r=10⁻⁶·Δt+3×10⁻⁷·θ`（rad²）。这些是模型配置，不是已证实符合本项目输入的统计标定结果；也不能用整个轨迹 RMSE 直接替代增量噪声标定。
- 普通地图因子在一次 NIS 准入后为二次代价；配置中的鲁棒核主要用于机会型回环，不会自动保护所有地图因子。错误且能通过门的绝对观测仍可能拉动图。
- 固定窗口只改变计算规模及保留的线性化历史，不会自动修正数据相关性或非高斯、多峰误匹配；多做一次 iSAM2 更新也不构成全局收敛证明。

## 2. 观测协方差：转换正确，统计解释有条件

### 2.1 点面信息如何得到

在目标参考系中左乘更新配准位姿。单点残差的一阶 Jacobian 为：

`J_i = [ n_iᵀ, −n_iᵀ [Rp_i+t]× ]`，后端切向量顺序为 `[平移,旋转]`。

源码用 Huber 权重构造 `H=Σ w_i J_iᵀJ_i`，从最终对应的残差估计：

`σ²=max(σ_floor², RMSE²·N/max(1,N−rank))`。

在保留数值可观方向后，平方根信息满足相应子空间内 `L_leftᵀL_left≈αH/σ²`。正常跟踪的 `α=1/累积帧数`，随后叠加局部共模协方差。来源：[registration_solver.cpp](../../xxu_nav_2026/src/z-localization/src/backend/src/registration_solver.cpp)、[pose_conditioning.cpp](../../xxu_nav_2026/src/z-localization/src/backend/src/pose_conditioning.cpp)。

**这些做法能限制单次测量过度自信，但仍是近似：**

- 平面及对应被当作给定，没有显式传播地图平面参数与参考地图位姿的不确定性。
- 累积源点由 `O_k⁻¹O_i` 拼接；拼接误差没有作为图中多个相关位姿变量联合求解，而被压缩成当前单个位姿测量。
- Huber 正规方程的曲率加残差尺度，不是对任意鲁棒残差分布都精确成立的估计器协方差；没有验证 sandwich 协方差或独立重采样覆盖率。
- `1/帧数` 不等于严格的有效独立样本数。跨次观测有无原始帧重叠取决于周期和实际源窗口，不能只凭用了五帧就断言跨次一定重叠。即便原始帧不重叠，地图平面和前端偏置仍可能共享。
- 单次共模方差下限不能阻止同一系统偏差在多次独立因子中重复积累信息。

解析反例：`z_i=x+b+ε_i`，同一地图偏差 `σ_b=5 cm`，独立噪声 `σ_ε=1 cm`，重复 100 次。均值真实标准差约 **5.001 cm**；若每次把同一共模方差作为独立测量噪声，模型给出约 **0.510 cm**，方差低估约 **96.2 倍**。该例只说明模型风险，数值并非对机器人实测的拟合。[计算与结果](data/backend_factor_graph_review_20261105/analytical_results.json)

### 2.2 左右扰动与 GTSAM 顺序

设局部测量 `T=T_ref_S`，`δ_left=Ad(T)δ_right`，则：

- `L_right=L_left Ad(T)`；
- `C_right=Ad(T⁻¹) C_left Ad(T⁻¹)ᵀ`；
- 进入 GTSAM 时把列/协方差分量从 `[平移,旋转]` 重排为 `[旋转,平移]`。

转换用的是配准局部位姿 `T_ref_S`。再左乘确定的 `T_map_ref` 时，右扰动不变，因此不需要重复乘一次地图系 Adjoint。源码此处自洽。[measurement.cpp](../../xxu_nav_2026/src/z-localization/src/backend/src/measurement.cpp)、[covariance.cpp](../../xxu_nav_2026/src/z-localization/src/backend/src/covariance.cpp)

ROS 的世界坐标位置加性误差不等于完整 SE(3) 左扰动，转换到局部切空间时不能凭绝对地图位置添加杆臂项。源码对此作了区分。当前依赖的 GTSAM 配置启用 `GTSAM_POSE3_EXPMAP`，其分量及 Adjoint 与本次探针一致；外部基准见 [GTSAM 4.2 Pose3 实现](https://github.com/borglab/gtsam/blob/4.2/gtsam/geometry/Pose3.cpp)。

### 2.3 单次共模方差的实现

源码先将信息转入局部右扰动，再用：

`L_newᵀL_new = Lᵀ(I+L C_common Lᵀ)⁻¹L`。

满秩时等价于给原协方差加 `C_common`；降秩时保留原零空间。这一矩阵操作本次数值核对通过。当前配置的下限为 5 mm / 0.02°，只能解释为已有参数值，不能据此宣称地图误差实际不大于该尺度。

## 3. NIS：计算成立需要独立性与校准前提

源码用白化创新 `r`、Jacobian `G` 和预测图联合边缘协方差 `P`，计算：

`S=I+GPGᵀ`，`NIS=rᵀS⁻¹r`，卡方自由度为实际残差行数，而非固定为 6。

同批多来源的 `GPGᵀ` 保留共享图变量引入的相关性。**但 `I` 假设测量残差已正确白化、不同测量噪声彼此独立，且与预测状态误差独立。** 图变量交叉协方差正确，不代表输入测量与预测之间的交叉协方差已经建模。[graph_innovation.cpp](../../xxu_nav_2026/src/z-localization/src/backend/src/graph_innovation.cpp)、[observation.cpp](../../xxu_nav_2026/src/z-localization/src/backend/src/observation.cpp)

若在未白化的 `z−h(x_pred)` 约定下存在 `C=Cov(e_pred,e_meas)`，正确创新协方差还含 `−HC−CᵀHᵀ`。忽略相关项可能使门更松或更紧，符号和作用不能只凭“共享前端”判断。与此同时，历史相关观测被反复当作独立因子可能低估 `P`；两类影响要分开测量。

本次从原 MCAP 读取真值和静态外参，按源时间插值，不作外推。使用与原诊断相同的虚拟传感器参考，再由每次捕获的 `predicted·odom⁻¹` 重建名义变换；没有重新运行定位算法。结果见[逐帧复算](data/backend_factor_graph_review_20261105/diagnostic_window.json)。

## 4. 优化结果如何变成 map → odom

### 4.1 正常可信路径

图更新后，源码取最新轨迹关键帧的**同一个 k、同一个传感器系、同一个前端 epoch**：

`M = T_map_odom = X_k* O_k⁻¹`。

随后高频输出：

`T_map_S(t)=M O(t)=X_k* [O_k⁻¹O(t)]`。

这把图在关键帧时刻的优化结果，沿前端后续相对运动传播到当前时刻。源码使用最新关键帧，而不是把旧观测位姿直接与当前高频里程计相除；延迟观测提交时图会更新存活节点，随后按最新轨迹锚重算规范。[localization_trajectory.cpp](../../xxu_nav_2026/src/z-localization/src/backend/src/localization_trajectory.cpp) 的 `updateGraphLocked`

若同样使用固定外参 `E=T_S_base`，则 `(X_k E)(O_k E)⁻¹=X_k O_k⁻¹`。因此传感器锚与底盘锚可以等价，但两侧必须使用同一时刻、同一外参。动态云台外参不能未经时间核对就当作固定 E。

本次探针验证了非零平移及 roll/pitch/yaw 下的时间传播与外参抵消。负对照故意用旧 `X_k` 除以当前 `O(t)`，确实丢失约 **0.4128 m** 后续运动；当前正常路径没有采用这种错误公式。

ROS 约定允许 `map` 定位校正发生离散变化，`odom` 应保持局部连续。因此“map→odom 有更新”本身不是设计错误；应检查同时间全局误差、校正来源、信任和消费者行为。[REP-105](https://github.com/ros-infrastructure/rep/blob/master/rep-0105.rst)

### 4.2 输出协方差不是 map → odom 的协方差

源码查询最新图节点的局部边缘协方差，重排后旋转成世界位置加性协方差作为输出锚；之后通过杆臂 Jacobian 和过程 Q 传播到高频传感器位姿。[pose_output.cpp](../../xxu_nav_2026/src/z-localization/src/backend/src/pose_output.cpp)、[graph_estimates.cpp](../../xxu_nav_2026/src/z-localization/src/backend/src/graph_estimates.cpp)

该量描述 `T_map_S(t)`，不是单独变换 `M=X_kO_k⁻¹` 的协方差。后者一般需要 X、O 的联合协方差及交叉项；两者共享前端信息，不能直接独立相加。当前没有独立发布 TF 协方差，这不构成 TF 消息本身的缺陷；但研究或下游融合不得误用输出位姿协方差。

高频传播还假设锚误差和后续相对运动误差可近似独立。在有共享 IMU 偏置、重叠匹配历史等情况下，这同样需要覆盖率验证。iSAM2 边缘量本身也是当前线性化图下的局部近似，不是多峰恢复假设的完整后验。

### 4.3 失信时的发布路径

若最后可信位姿为 F，当前前端位姿为 O(t)，源码输出：

`T_map_S_output(t)=F`，`M_output(t)=F O(t)⁻¹`。

因此即便图中名义 M 不变，发布 TF 也会抵消前端运动。恢复后改回 `M O(t)`，累积运动会一次体现到输出上。这是冻结绝对位姿的后果，不能将全部释放角度归因于图优化错误。[pose_output.cpp](../../xxu_nav_2026/src/z-localization/src/backend/src/pose_output.cpp) 的 `TrustedPoseProjector::project`

标准 Odometry 仍沿用当前输入时间戳发布旧位姿；虽提高方差、清零速度并独立声明不可信，普通消费者仍可能把它当作当前时刻的测量。[publisher.cpp](../../xxu_nav_2026/src/z-localization/src/backend/apps/publisher.cpp) 的 `publishOdometry`

判断：冻结可以作为诊断或明确约定的失信表示，但应与有效的当前全局定位输出区别表达。具体输出协议修复尚未实施；本研究也不主张仅停 TF 就能替代状态、时效及速度门保护。

## 5. 下一步最小研究与验证顺序

1. **固定 TF 片段的输入/相对运动溯源。** 使用上述 runtime 248–254，核对前端观测位姿、逐点时间、IMU 积分、虚拟传感器补偿和同时间真值，明确 0.46559 m 相对误差从何产生。避免先靠放松全局门吸收输入错误。
2. **分开校准 Q 与 R。** 用独立路线、不同转弯速度，分别评价里程计增量的方向性/时间相关、固定真值下单帧与多帧配准误差；保留平移旋转完整耦合，统计创新白化与覆盖率。数据按路线划分，避免在同一调参路线自证。
3. **评估相关性规模。** 分开比较单帧/累积源、跨次不重叠/重叠、同一地图/独立地图，测量共模偏差及创新自相关。只有证据表明现有近似不足，才比较共享偏置、地图不确定性或保守融合等候选；不预先新增模块。
4. **保持恢复与输出问题独立验证。** 先按既有同批证据研究候选准入，再验证恢复锚的真实性、冻结发布契约及消费者重新放行。不能把“接受几何最佳”直接等同于可信定位，也不能用更高传播频率掩盖旧状态。
5. 因子图层若提出改动，使用固定源及线性解析负例、重复回放、独立路线与隔离 Nav2 闭环逐级确认。只在可重复改善且相关回归完成后考虑修改默认。
